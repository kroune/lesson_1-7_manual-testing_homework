## BUG-01. Слишком короткое имя проходило проверку

- Ожидалось: ошибка валидации, новой заявки нет.
- Получилось; свидетельство: появилась четвёртая заявка, в localStorage сохранено имя `А`.
- Исправление: `src/app.js`, имя обрезается до валидации и отправки; commit `9f29f4d`.
- Повторная проверка с теми же данными и результат: ошибка «от 2 до 60 символов», осталось три заявки.
- Соседняя проверка и результат: `  Иван Петров  ` сохранено без крайних пробелов; границы 2/60 символов имени и 200 комментария принимаются, 61/201 отклоняются.

## BUG-07. Комментарий обрабатывался как HTML

- Требование и влияние на пользователя: R7; введённые символы не отображались как обычный текст.
- Условия: обычный режим, комментарий `<b>жирный</b>`.
- Данные и шаги: отправить заявку, открыть карточку и подробности, перезагрузить страницу.
- Ожидалось: во всех местах виден текст `<b>жирный</b>`.
- Получилось; свидетельство: в карточке и подробностях появлялся элемент `b`, виден только текст «жирный»; разметка сохранялась после перезагрузки.
- Исправление: `src/app.js`, `innerHTML` заменён на `textContent`; commit `9f29f4d`.
- Повторная проверка с теми же данными и результат: текст отображается полностью, элемента `b` нет.
- Соседняя проверка и результат: после перезагрузки комментарий и подробности остаются обычным текстом.

## BUG-08. Ошибка сервиса показывалась как успех

- Ожидалось: сообщение об ошибке, значения полей сохранены, новой заявки нет, повтор доступен.

- Исправление: `src/app.js`, проверяется `response.ok`, ошибка передаётся в обработчик; commit `9f29f4d`.
- Повторная проверка с теми же данными и результат: видна ошибка 503, значения сохранены, новой заявки нет, кнопка доступна.
- Соседняя проверка и результат: повтор в обычном режиме сохраняет одну заявку и очищает форму.

## Бонусы

| Пункт | Действия и результаты проверок |
| --- | --- |
| T1 | Две попытки и попытки с интервалом больше 5 секунд — без сигнала. Шестое обновление за 5 секунд — T1; чтение карточек доступно. |
| T2 | `supportCode=bot` через DevTools — T2, заявка не создана. Обычное заполнение оставляет поле пустым, инцидента нет. |
| T3 | Вызов скрытой `staff-export` — T3, выгрузки нет. Tab и обычное обновление — без сигнала. |
| T4 | Подмена направления на `other` — T4, заявка не создана. Пустое направление — обычная ошибка валидации без инцидента. |
| T5 | `canary` с `role: "admin"` — T5 при загрузке, маркер восстановлен в `visitor`. Повторная загрузка не добавляет событие; повреждённый JSON — без сигнала. |
| T6 | `?staff=1&from=test` — T6, `staff` удалён, другой параметр сохранён. Повторная загрузка не добавляет событие; `staff=0` — без сигнала. |
| Журнал | Время, тип и причина сохраняются и восстанавливаются после перезагрузки. После 35 пробных событий остаётся 30; повреждённый JSON не ломает приложение. |
| Ограничение | После инцидента видны причина и таймер, submit и обновление блокируются в обработчиках. Чтение доступно; через 30 секунд обе функции снова работают. |
| blockedUntil | После перезагрузки сохраняется прежнее время окончания. Повторные попытки его не продлевают; сброс стенда очищает журнал, таймер и ограничение. |
| GitHub Pages | https://kroune.github.io/lesson_1-7_manual-testing_homework/ — обычный сценарий, ловушка и восстановление журнала проверены на опубликованной версии. |
